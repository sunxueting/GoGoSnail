# 1.1.8 死亡瞬间遮罩与成绩同步修复

用户确认 240 分是在参加全服排名后取得，但全服最高仍为 167；并明确遮罩缺口出现在刚死亡时。此前 1.1.7 仅覆盖后续稳定结算页，未覆盖死亡第一帧的独立动画层。

## 两层死亡遮罩

`PlayerControl.missionFailed` 先显示 `UILayer/Blink_White/white`，延迟约一秒后才显示 `deathboxUp/OverGameBg`。前者仍使用固定 1080×1920 大小。现在死亡和结算入口都同步适配，按屏幕四角逆变换绘制覆盖区域，跟随父节点及相机变化，保留动画渐隐和结算黑色半透明效果。

旧版 Graphics 渲染器不可靠地继承动画节点透明度，因此死亡动画透明度直接编码进填充颜色，透明度为零时隐藏绘制节点。防止全屏修复后留下不透明黑层。

## 成绩同步

- 开局不再依赖尚未返回的排行榜缓存；服务器校验是否已参加，不隐式加入排行榜。
- 死亡立即发起本局成绩提交。网络和限流错误最多重试两次；只有云端确认后才提示成功并刷新全服最高分。
- 新局请求等待上一局开局/成绩请求完成，避免立即重开取消旧成绩或替换其服务端令牌。同一局复活后的更高成绩串行提交，服务端最高分不会回退。
- 当前局同步失败时保留本机成绩和重试入口。超时设为 25 秒，覆盖云函数 20 秒超时及通信开销。退出排名取消排队请求，过期回调不能恢复成功提示。
- 排行榜分别显示云端纪录与更高的本机纪录。离线、本机历史纪录不冒充已经确认的云端成绩。

这些缺陷可以导致用户报告的差异，但未读取该用户手机的历史运行日志，不能断言 240 分具体命中了哪一条路径。旧版没有持久保存失败对局的服务端令牌，已结束或重启后的历史 240 分无法仅凭本机最高分安全补传。本版未直接修改生产数据库，也未增加历史成绩导入接口。新成绩仍在死亡时上传，并非每得一分立即请求云端；关闭微信前尚未完成的请求不保证恢复。

## 验证

`test:score-sync` 使用合成传输测试：无缓存冷启动将云端 167 更新为本局 240、两次网络失败后成功、重试耗尽后手动重试、开局失败重试、立即重开、同局高分并发、未参加及退出取消。没有使用真实用户数据。

`test:layout` 增加三种尺寸下死亡第一帧同步创建、四角实际像素、半透明和父节点移动检查，并保留七种结算尺寸、安全复活、触摸恢复检查。另验证玩法、复活、性能、排行榜 UI 和连续地图生成。网页、模拟传输测试和官方预览编译均不等同于用户手机确认。

2026-10-29 官方 CLI 已生成 1.1.8 手机预览，总包 5,586,639 字节。手机需扫描本次新码确认版本，再检查死亡瞬间四边与一局结束后的同步提示、本人云端纪录和全服最高。尚未上传为开发版本、提审或上线；线上云函数无需变更。
