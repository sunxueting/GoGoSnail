# 微信云开发排行榜部署

2026-10-29：用户已选用微信云开发。1.1.5 代码及本地多用户验证已准备，**尚未部署、环境 ID 为空、全服功能尚未启用**。不要把本地合成玩家截图当成实际云端玩家数据。历史 1.1.4 上传包保持原样。

## 环境与费用

使用小游戏 `wx60136090bb46174f` 的微信云开发环境。必须确认环境与此 AppID 的关联；不要使用另一个小程序的环境。当前官方 CLI 无论按项目还是直接按 AppID 查询，均返回微信接口 `ret:1000, system error`，这不代表账号一定没有环境。

请先从微信开发者工具顶部云朵图标核对已有环境。若没有环境，在开通页确认数据库支持文档型集合、云函数及微信身份透传，再选择适合的免费体验或个人套餐。实际费用、期限、超限策略与自动续费以账号开通页为准；用户尚未授权购买套餐或接受新服务协议。暂不为此项目购买阿里云服务器。

## 数据与权限

1. 创建文档型集合 `snail_players`。客户端的读取和写入权限均设为 `false`，见 `cloudfunctions/database.rules.json`；仅云函数以服务端权限访问。
2. 按 `cloudfunctions/database.indexes.json` 建立联合索引：`participating` 升序、`hasScore` 升序、`best` 降序、`_id` 升序。该文件是部署清单，**构建或上传云函数不会自动创建数据库集合、权限或索引**。
3. 玩家身份从云函数 `getWXContext()` 获取，并校验 APPID。客户端传入的 openId 不生效。数据库文档 ID 为 APPID 与 OpenID 的 SHA-256，排行榜响应不返回 OpenID 或内部文档 ID。
4. 每位明确参加的玩家保存一个历史最高分和一个当前对局。成绩与参与数据由数据库事务更新。同分并列，显示完整榜单的分页结果和本人名次。
5. 头像昵称在用户另行同意公开、当前隐私及用户信息权限有效、文本和图片检查通过后才公开。检查失败或接口不可用时不会发布本次资料。本机已有授权不会自动上传。
6. 玩家可撤下云端头像昵称，或退出并删除自己的整个云端记录。本机纪录与本机资料分别管理；本机“删除头像昵称”不会冒充已删除云端资料，全服页有独立的撤下与退出入口。

## 云函数

目录为 `cloudfunctions/snailLeaderboard`，入口 `index.main`；运行时使用平台支持的 Node.js 18 或更高版本。依赖已锁定 `wx-server-sdk@4.0.2`。在控制台将函数超时设置为 **20 秒**，内存从 256 MB 起验证；确认该配置实际生效，不能假设 `config.json` 已设置超时。

需要微信内容检查 API 权限：`security.msgSecCheck`、`security.imgSecCheck`，在函数 `config.json` 中声明。还需在真实环境确认此小游戏账号当前可调用这两个接口；若图片同步检测不可用，应接入平台当前支持的异步审核及回调后再开放头像公开，不能直接跳过检查。

已有环境 ID 后，使用官方开发者工具 CLI 部署（示例中的环境 ID 必须替换为实际值）：

```sh
/Applications/wechatwebdevtools-arm64.app/Contents/MacOS/cli cloud functions deploy \
  --appid wx60136090bb46174f \
  --env ACTUAL_ENVIRONMENT_ID \
  --paths "$PWD/cloudfunctions/snailLeaderboard" \
  --remote-npm-install
```

部署后在 `source/assets/Script/CloudRankingConfig.js` 写入实际公开环境 ID，函数名保持 `snailLeaderboard`；重建游戏。环境 ID 不是密钥，任何 AppSecret、腾讯云 SecretId/SecretKey 都不能进入小游戏包或 Git。

`npm run build` 把云函数目录复制到微信开发工程，方便工具识别；微信代码包通过 `packOptions.ignore` 排除该目录。云函数的部署与小游戏上传是两项操作。

## 上线前的实际验证

- 用两个微信账号在同一真实环境参加排行榜，完成不同成绩的对局；核对两台手机的全服最高、榜单和本人名次一致。较低分的新一局不能覆盖历史最高分。
