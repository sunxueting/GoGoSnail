# 免广告复活点击实验（1.1.6 起）

玩家在结算页看到视频图标与“看广告复活”。点击后不创建、加载或展示广告，直接恢复当前对局的全部生命值、无敌状态及操作，并显示“本次免广告／已为您满血复活！”。保留当前得分，每局一次，倒计时结束或已领取后不能再次领取。其他版本、审核人员和普通玩家采用同一逻辑。

## 实际上报

使用微信原生 `wx.reportEvent(eventId, data)`，不安装广告或第三方统计 SDK。不调用仅在小程序旧接口中出现的 `wx.reportAnalytics`。微信官方小游戏接口定义确认 `reportEvent` 需要基础库 2.14.4；客户端通过能力检测兼容缺失情况。

| 事件英文名 | 含义 | 触发口径 |
| --- | --- | --- |
| `snail_play_start` | 开始实际游玩 | 新对局开始，继续复活不重复算开局 |
| `snail_revive_show` | 复活入口曝光 | 结算页中仍可领取且实际激活显示的按钮，每局一次 |
| `snail_revive_click` | 点击复活入口 | 有效按钮第一次被领取；过期、重复回调和二次复活不计 |
| `snail_revive_success` | 实际复活成功 | 当前对局已恢复后上报；失败不报成功 |

四个事件均使用以下**字符串**字段：

| 字段 | 当前值 |
| --- | --- |
| `placement` | `gameover_revive` |
| `experiment` | `no_ad_v1` |
| `reward_mode` | `free` |
| `version` | 当前 ReleaseConfig.version（现为 `1.1.8`） |

同一人不同对局仍会产生多次事件，由微信后台的用户去重指标计算人数。代码不生成跟踪 ID，不将昵称、头像、OpenID、云端玩家标识或分数放入埋点，也不写入本地事件队列或排行榜数据库。无法上报、接口抛异常和普通浏览器运行均不能阻止复活；不等待统计响应发奖。`reportEvent` 返回不代表平台已经接收或展示数据。

2. 在支持用户去重的事件报表中，选择同一日期范围、同一实际测试版本（现为 `1.1.8`）、同一实验 `no_ad_v1` 和入口。分别查询事件的**去重人数（UV）**和总次数（PV）；若当前页面只有次数，需要先找到支持用户去重的分析报表，不能以次数冒充人数。
3. 用两个微信账号真机验证：两人均看到入口，仅一人点击，多玩一局并重复点击；确认曝光 UV=2、点击 UV=1，而次数可以更大。这是验收示例，不是已取得的运营数据。还应检查 `snail_revive_success` 与实际恢复一致。
4. 排除开发工具、自动化和运营自测流量；后台若提供版本/环境筛选，应分别查看开发预览和正式玩家。聚合整段时间的 UV，不把每日 UV 相加当作多日人数。

截至本次代码修改，未在微信后台创建/验证这些事件，未验证真机入库，也未获得真实玩家点击率。既有后台页面控制超时问题尚未解决。这里只完成代码与可复现的本地验证。

## 指标

- **广告位吸引力（主要指标）** = `snail_revive_click` 去重人数 ÷ `snail_revive_show` 去重人数 × 100%。分母为实际看到这个入口的玩家。
- **全体游玩玩家点击占比** = `snail_revive_click` 去重人数 ÷ `snail_play_start` 去重人数 × 100%。包括尚未死亡、没看到入口的玩家，因此单独列出。
- **按曝光次数的点击率** = 点击 PV ÷ 曝光 PV × 100%。不能与前两个玩家比例混用。
- **发奖成功率** = 成功 PV ÷ 点击 PV × 100%。用于排查点击后未恢复的问题。

分母为 0 显示“暂无数据”，不显示 0% 或无穷大。使用相同时间、版本和过滤条件；跨日期漏斗分析时使用平台的用户级漏斗，避免只按同一天划分造成跨日点击丢失。

玩家会逐渐知道入口免广告，此实验只能评估当前按钮的点击意愿，不能当成真实广告播放、完播、广告收入或真实等待成本下的点击率。后续若接入真实广告，应另设实验标识，不能混合统计。

## 隐私和提审资料同步

除之前排行榜的披露外，隐私说明还需如实增加“游戏操作事件”用途：通过微信原生分析处理开始游戏、复活入口曝光、点击和复活成功事件，用于评估入口使用情况和修复发奖问题；本游戏不主动附带头像昵称或业务用户标识。不能把平台处理的分析数据宣称为完全没有任何个人信息处理。

产品说明应明确“视频图标入口当前免广告直接复活”，不能宣称已接入广告或有真实广告收入。本次未修改微信后台协议或重新提审。

## 本地验证

`npm run build && npm run test:revive` 运行真实 Cocos 场景与触摸，模拟微信原生事件 API。验证重复回调、过期入口、每局一次、当前分数保留、满血恢复、免广告提示、四种屏幕、统计接口缺失/抛错，以及三名合成玩家的 UV/PV 分母区别。报告 `artifacts/revive-offer-check.json` 和截图均为本地测试，不能作为真实玩家数据。
