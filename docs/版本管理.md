# 版本管理

默认分支为 `master`，保留原仓库提交历史。日常修改建议新建 `codex/功能名称` 分支，验证后合并到 `master`。

## 日常流程

```sh
git pull --ff-only
git switch -c codex/example-change
npm ci
npm run build
npm test
npm run test:profile
npm run test:layout
git add source tools docs package.json package-lock.json
git commit -m "Describe the change"
git push -u origin codex/example-change
```

GitHub 提出拉取请求，核对差异并等待自动检查；通过后合并。不要提交 `node_modules`、生成目录、个人开发者工具配置、预览码、身份资料或凭据。本机运营记录和操作排障材料也不上传。

## 提审和发布

1. 同步 `package.json`、锁文件及游戏版本文案，更新 CHANGELOG 和版本记录。
2. 构建并完成与改动相符的本地、微信模拟器及真机检查。
3. 通过官方工具上传，记录准确的 Git 提交、上传版本与审核状态。
4. 以 `v版本-review` 标记提审源码快照；此标记不表示线上发布成功。
5. 微信审核通过且实际发布后，记录上线结果，再建立相应发布标记。
